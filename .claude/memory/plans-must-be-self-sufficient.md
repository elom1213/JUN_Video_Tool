**계획서는 "계획서만 보고도 작업을 시작할 수 있도록" 작성한다.** 사용자가 2026-10-14 에 Draw 탭 계획서를
요청하면서 지정했고, 앞으로 이 저장소에서 계획서를 쓸 때마다 적용되는 조건이다.

**Why:** 계획서는 다음 세션(또는 다른 PC · 다른 사람)이 코드와 대화 이력 없이 그것만 들고 구현에 들어가는
출발점이다. 방향만 적힌 계획서는 다시 설계부터 하게 만든다.

**How to apply:**
- 파일 · 클래스 · 메서드 시그니처 · 시그널 · 상수값 · 설정 키 · 단축키 · 데이터(JSON) 스키마를 **실제 이름으로** 적는다.
- 결정이 갈리는 지점은 후보 비교표 → **결정 + 이유** 로 닫아 둔다. "검토 필요" 로 남기지 않는다.
- 기존 코드를 옮기는 작업은 "무엇이 어디로" 이동 표를 넣는다.
- 핵심 계산 규칙은 입력 → 기대값 예시로 적어 그대로 테스트가 되게 한다.
- 구현 순서는 단계별 **완료 기준**(앱이 뜨고 pytest 가 통과하는 상태)과 함께 쓴다.
- 리스크마다 대응을 적고, 범위 밖 항목을 명시한다.
- 기존 양식은 `docs/PLAN.md`, `docs/PLAN_DRAW_TAB.md` 를 따른다. 설명은 한국어, UI 문자열 · 식별자는 영어.
